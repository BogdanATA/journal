## Phase Goal

**As a** person writing into a plain text file, **I want to** know that quitting the app, switching windows, or typing anything at all never costs me a character, **so that** I can stop thinking about saving entirely.

<objective>
Harden the durability contract the tracer established: extend the flush from blur-only to the full D-02 set (window close and day navigation), serialize concurrent writes, and prove that the text transform between the editor buffer and the file on disk is the identity function.

Purpose: WRITE-02's promise is "autosaved continuously without an explicit save action" and the ROADMAP's success criterion is that content survives an app crash or force-quit mid-write. The debounce alone leaves a 1.2-second window; the close-request interception is what closes it for a normal quit. The fidelity work exists because the app's other promise — a plain Markdown file readable anywhere — is worthless if the app quietly rewrites what the user typed.

Output: an autosave path that a person can trust without a save indicator (D-03), plus `node --test` coverage that pins the byte-fidelity and blank-line-boundary contracts so Phase 2's tag pills cannot regress them.
</objective>

| T-01-05 | Denial of Service | `onCloseRequested` handler in `src/app/App.tsx` | high | mitigate | A rejected or hung flush must never make the app unquittable. `destroy()` is called from a `finally` block so it runs on both success and failure, and a re-entry ref makes a second close request destroy immediately instead of queueing another flush. |

| T-01-07 | Tampering | `saveDay` write-skip and clear-to-empty handling | medium | mitigate | The skip rule only suppresses creating a *new* file for a never-typed day; it never removes an existing one. A verify gate asserts `dayFile.ts` contains no remove call. |
| T-01-08 | Information Disclosure | day-file content transform | low | accept | The identity-transform requirement means the app never inspects, rewrites, or re-encodes the user's text — the content is only ever moved between the buffer and the file. ## Flagged assumptions

1. **Write atomicity (RESEARCH.md A2 / Open Question 2)** — carried forward as a `backstop` truth. Flush-on-blur/close shrinks the in-flight window but `plugin-fs` guarantees nothing about a kill mid-`writeTextFile`. Write-to-temp-then-rename is deliberately deferred until UAT shows real corruption; adding it speculatively would trade a documented, bounded risk for untested complexity.
2. **`onCloseRequested` on Windows** — the handler behaviour is verified locally on macOS only, because this machine cannot run Windows. Plan 04's CI produces the Windows installer but does not exercise the quit path; the Windows quit-flush check belongs in end-of-phase UAT.
3. **CodeMirror does not rewrite the buffer** — the identity guarantee is asserted at the storage layer. If CodeMirror itself normalizes line endings on input (a real possibility for pasted CRLF text), the file will hold CodeMirror's normalization, not the paste's. Surfaced here rather than assumed away; the round-trip test covers the storage layer and the human-check covers the editor layer.
